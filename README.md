# research-jev

Research notes on Jev / System One as a typed decision layer for AI agents, with a focus on coding-agent runtimes.

## Research question

How can bounded, typed decisions be moved out of an expensive frontier-model loop and into a cheaper decision layer without losing control, calibration, or auditability?

## Working hypothesis

Jev is most useful to study not as a small LLM, but as a typed decision layer inside an agent runtime.

A coding-agent loop repeatedly makes bounded decisions around the main generation step:
1. Which files? — select relevant context.
2. Which model? — route the task to an appropriate model/effort tier.
3. Safe to run? — gate tool execution and destructive actions.
4. Done? — decide whether evidence supports termination.
5. Keep or drop? — retain, compress, or discard tool output/history.

The research question is whether these decisions should be represented explicitly as typed runtime policies rather than generated as prose and parsed back into control flow.

## Literature / ecosystem map

### Agent runtime and coding-agent loops

Coding agents can be understood as an outer loop around an LLM: observe state, choose tools/actions, execute, inspect results, and decide whether to continue. This makes the runtime—not only the base model—a major optimization surface.

### Context engineering

Dynamic context discovery, selective tool/schema loading, retrieval, and context compression address the same pressure as Jev's Which files? and Keep or drop? decisions.

Important questions:
- What context must be present for a decision?
- Can large tool outputs remain externally addressable instead of entering every prompt?
- Can context be selected with bounded decisions before invoking the frontier model?

### Model routing

Session-aware routing treats model choice as a runtime decision rather than a fixed property of the agent. This directly corresponds to Which model?

Important questions:
- When is a frontier model actually necessary?
- Can routing exploit cached state and agent phase?
- What is the cost/quality trade-off of switching models?

### Tool gating and safety

Tool-use research treats whether to call a tool as a decision problem. This corresponds to Safe to run?, especially when actions are irreversible or have external side effects.

Important questions:
- Should policy gates be independent of the generation model?
- Should uncertainty cause deny, ask-human, or retry?
- Can every tool decision be logged and replayed?

### Termination and evaluation

Done? is a distinct evaluation problem. A coding agent needs evidence that the requested change is complete, not merely a plausible textual response.

Important questions:
- What evidence is sufficient for termination?
- Can tests, diffs, and runtime observations become typed inputs?
- How should uncertainty trigger another loop or human review?

## Five-decision runtime model

Agent Runtime -> Which files? / Which model? / Safe to run? -> Frontier LLM -> Generate / modify -> Test / observe -> Done? -> Keep / drop? -> LOOP

## Research direction

Compare three architectures:

A. Frontier-only — all decisions are generated by the same frontier model.
B. Typed-decision gateway — bounded decisions are delegated to Jev-like calls; the frontier model handles open-ended generation/reasoning.
C. Local typed-decision runtime — an open model reads option probabilities directly and performs bounded decisions locally.

Evaluate:
- cost per completed task
- latency
- token/context usage
- tool-call count
- task success
- false termination
- unsafe-action rate
- calibration / abstention
- reproducibility
- auditability

## Open-source reproduction

bonsai/openjev provides an independent reproduction of the typed-decision interface pattern using open models. It reports direct typed logits, shared-state reuse, and comparisons with autoregressive JSON output. It explicitly does not claim to reproduce TypeSafe's undisclosed Jev model.

This is especially relevant for local-runtime research because it separates the architectural idea from the proprietary model.

## Current ecosystem observations

The September 2026 Jev ecosystem already contains experiments around coding-agent model routing, tool-call guardrails, context filtering, evaluation, retrieval/reranking, computer/browser use, local typed-decision models, and MCP integrations.

These should be treated as implementations to inspect, not as evidence that Jev improves every workload.

Do not treat a community benchmark or reported cost reduction as a general guarantee.
